# 04 · Prior art: products that already do parts of what Evrakçı does

Research date: 2026-11-27. Every claim has a source link next to it. A claim marked **(unverified)** comes only from a secondary source, a search snippet or my own inference, and I did not confirm it in a primary document. Review-site summaries (G2, Capterra, TrustRadius) are based on small samples and are often several years old. Read them as signals, not measurements.

---

## 1. The short version

- **Open-source document management (DMS) tools** (Paperless-ngx, Mayan, Docspell, Teedy, Papermerge) are all **web servers**: Docker, a database and a task broker. Their job is to archive and search documents. They are not built to capture data or fill forms. Paperless-ngx says outright that it "runs on Linux only, Windows is not supported" ([setup.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/setup.md)). None of them reads values from fixed boxes on a form (zonal OCR) in a way a clerk could set up.
- **Open-source desktop tools** (NAPS2, PDF Arranger, ScanTailor Advanced, gscan2pdf, OCRmyPDF) each do one step well: scan, rearrange pages, clean images, or add a text layer. None of them holds a "job", a review queue or a template.
- **Commercial capture suites** (ABBYY FlexiCapture, Kofax/Tungsten Capture, PaperStream Capture, Laserfiche Quick Fields, DocuWare) have the right concepts: batch classes, document definitions, separation profiles, scan, then verification, then release. Users praise their accuracy and complain about complexity, cost and the need for IT staff.
- **Office and PDF tools** (Word, LibreOffice mail merge, Acrobat, Foxit, PDF-XChange) handle filling documents from data. Each has well-known traps: formats lost in merge, no multi-row fill into PDF forms, and crashes.
- **Turkish EBYS systems** (Türksat Belgenet, Bimser eBA and others) are built for official correspondence under the TS 13298 standard, e-signature (e-imza) and registered e-mail (KEP). They are not tools for capturing data from scanned paper or filling forms on a desk.

## 3. Product notes

### 3.1 Paperless-ngx: the most popular open-source DMS
- **Pipeline.** A "consumer" watches a folder, mail or API uploads. Workflows fire on five triggers (Consumption Started, Document Added, Document Updated, Scheduled, Manual) and run assignment, removal, email, webhook and similar actions in sort order ([usage.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/usage.md)). Version 2.3 replaced "Consumption Templates" with Workflows ([usage.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/usage.md)).
- **Splitting.** `PAPERLESS_CONSUMER_ENABLE_BARCODES` turns on barcode splitting. The separator string defaults to `PATCHT`, and the separator page is dropped unless `..._BARCODE_RETAIN_SPLIT_PAGES` is set. ASN barcodes and tag barcodes split documents and keep the barcode page ([configuration.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/configuration.md), [advanced_usage.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/advanced_usage.md)). This is very close to Evrakçı's QR-separator idea, and it shows two separator semantics (drop the page vs keep the page) that users rely on.
- **Data.** Custom fields with types (number, date, string…) are entered by hand on the document detail page ([usage.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/usage.md)). I found no zonal or template OCR that fills those fields from a box on the page (unverified absence: I found no discussion of it).
- **Review.** The recommended process uses an "inbox" tag on every new document and a TODO tag, plus a physical binder sorted by ASN ([usage.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/usage.md)). Review is a tag, not a state machine.
- **Sharing.** Each object has an owner and view/edit permissions ([usage.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/usage.md)). Approval workflows with an "assigned to" field are an open feature request ([discussion #3625](https://github.com/paperless-ngx/paperless-ngx/discussions/3625)).
- **Complaints.** Beginners get stuck at Docker: "I don't even know what a docker is… not compatible with my Windows 11 Pro" ([r/selfhosted mirror](https://axebps-redlib.hf.space/r/selfhosted/comments/171rd8n/a_deep_dive_into_paperlessngx/lo5u98g/?context=3)). It is Linux-only by policy ([setup.md](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/setup.md)). One partisan Mayan user says Paperless "would just choke" past 10k documents ([Mayan forum](https://forum.mayan-edms.com/t/a-little-love-for-the-devs/1179), anecdote, unverified).
- **Praise.** It is the community favourite for personal and small-office archiving ([needtoknowit](https://needtoknowit.com.au/blog/paperless-ngx-on-nas-is-it-worth-the-setup-complexity.md); [Mayan forum thread](https://forum.mayan-edms.com/t/help-me-decide-which-to-choose/1293)).

### 3.2 Mayan EDMS
- Django + Celery with a RabbitMQ or Redis broker. It needs at least 2 GB RAM, or 1 GB with OCR off ([PyPI 4.4](https://pypi.org/project/mayan-edms/4.4)).
- It has the most formal **workflow model** of the open-source DMS tools: states, transitions, state actions and transition fields ([docs](https://docs.mayan-edms.com/apps/document_states/index.html), [PyPI 3.3](https://pypi.org/project/mayan-edms/3.3)). A workflow attaches to **one document by design** ([forum](https://forum.mayan-edms.com/t/one-workflow-for-more-than-one-document/260)). A batch-level "job" does not fit this model. Documentation gaps around transition fields were reported ([GitLab #727](https://gitlab.com/mayan-edms/mayan-edms/issues/727)).
- Users see it as harder to set up ("Complex Setup", [SaaSHub](https://www.saashub.com/compare-mayan-edms-vs-papermerge-dms)) and some call it "bloated" ([Mayan forum](https://forum.mayan-edms.com/t/a-little-love-for-the-devs/1179)).

### 3.3 Docspell, Teedy, Papermerge, OpenKM
- **Docspell** splits a REST server/UI from "joex", which runs long jobs, over a shared DB. It shells out to tesseract, unoconv and ocrmypdf ([README](https://raw.githubusercontent.com/eikek/docspell/master/README.md)). It suggests correspondents, tags and dates with Stanford CoreNLP, learning from existing documents ([README](https://raw.githubusercontent.com/eikek/docspell/master/README.md)). It is **AGPLv3+**, the same licence family Evrakçı plans to use. It appears actively maintained ([ideaproof](https://ideaproof.io/open-source/project/docspell), aggregator, unverified).
- **Teedy** has a "Workflow system" with route steps of two types: `APPROVE` ("2 choices") and `VALIDATE` ("no possible choice") ([source](https://raw.githubusercontent.com/sismics/docs/master/docs-core/src/main/java/com/sismics/docs/core/constant/RouteStepType.java)). It also has an audit log, comments, file versioning and a bulk importer ([README](https://raw.githubusercontent.com/sismics/docs/master/README.md)). The two step types are a minimal model Evrakçı could reuse for "finished / not finished" sign-off.
- **Papermerge** offers a "desktop-like" web UI: dual panel, drag and drop, page management (delete, reorder, cut, move, extract) and custom fields per document type ([README](https://raw.githubusercontent.com/papermerge/papermerge-core/master/README.md)).
- **OpenKM CE** stopped publishing source with 7.0 and is now binary freeware. The company's stated reason is third parties reselling the code ([OpenKM blog](https://www.openkm.com/blog/openkm-community-edition-v70-a-new-stage-for-open-source-document-management.html)). This is a cautionary tale for any dual-licence project.

### 3.4 Desktop single-step tools
- **NAPS2** is the closest analogue to a Windows-native, non-technical scanning UI. Batch scan can "Separate files by Patch-T", and patch codes need at least 300 DPI ([NAPS2 docs](https://www.naps2.com/doc/batch-scan)). Splitting by an arbitrary QR value was requested in 2018 ([SF ticket #478](https://sourceforge.net/p/naps2/tickets/478/)). TWAIN from a 64-bit process needs a 32-bit worker ([NAPS2 SDK/NuGet](https://www.nuget.org/packages/NAPS2.Sdk)). The scanning SDK is LGPL ([NuGet](https://www.nuget.org/packages/NAPS2.Sdk)).
- **OCRmyPDF** supports Windows, but it depends on separately installed Tesseract and Ghostscript, which it finds via `PATH` or the Registry ([README](https://github.com/ocrmypdf/OCRmyPDF)). Older docs called native Windows "beta" and warned that mixing 32-bit and 64-bit builds "will lead to errors" ([v14.1 install docs](https://ocrmypdf.readthedocs.io/en/v14.1.0/installation.html)). It has a plugin interface for other OCR engines ([README](https://github.com/ocrmypdf/OCRmyPDF)).
- **PDF Arranger** is a thin GTK front end over pikepdf ([GitHub](https://github.com/pdfarranger/pdfarranger)). It is well liked because it does one job with thumbnails.
- **ScanTailor Advanced** merged the Featured and Enhanced forks. The original 4lex4 repo "seems to be no longer active", so a community fork carries it on ([Gitea](https://gitea.com/ImageProcessing-ElectronicPublications/scantailor-advanced)). It highlights pages in red when their skew, content size or margins differ from the rest of the set ([Gitea](https://gitea.com/zvezdochiot/scantailor-advanced)). That is a good review pattern.
- **gscan2pdf** chains scan, rotate, unpaper and OCR, and that chaining needed repeated fixes ("Fixed scan->rotate->unpaper->OCR chaining (again)") ([SF](https://sourceforge.net/projects/gscan2pdf)).
- **Stirling-PDF** has 50+ tools, a desktop client and no-code pipelines, with its UI in 40+ languages ([README](https://raw.githubusercontent.com/Stirling-Tools/Stirling-PDF/main/README.md)). Its QR divider-page auto-split is in the source ([mirror commit](https://homehud.duckdns.org/javier/Stirling-PDF/commit/0233086487b15149c2784e7451754fbe6d055416?files=src), secondary). The open-core move caused backlash. Paid features are gated "via just configuration changes" ([isitreallyfoss](https://isitreallyfoss.com/projects/stirling-pdf/)), organisations over 5 users need a licence ([heise](https://heise.de/-11095732)), and users complained about features that used to be free going behind the paywall ([Cloudron forum](https://forum.cloudron.io/topic/14224/stirlingpdf-license-user-limit-changes/4)).

### 3.5 Commercial capture
- **ABBYY FlexiCapture.** The server side has an Application Server (IIS), License Server, Processing Server, DB and file storage. Clients are the Project Setup, Scanning and Verification stations ([admin guide](https://docs.abbyy.com/flexi-capture/admin-guide/architecture-ag)). For fixed forms, "identical fields have exactly the same locations", and they are defined in a Document Definition. Semi-structured documents use FlexiLayout Studio ([FLS](https://docs.abbyy.com/flexi-capture/fls/overview/about)). The **Standalone** edition runs on one PC with Administrator and Operator stations. It is meant for 2–3 operators in shifts, without complex batch routing ([v12 help](https://help.abbyy.com/en-us/flexicapture/12/admin_guide/standalone)). Users praise its accuracy, find setup complex and model training reliant on IT, and call it pricey ([G2](https://www.g2.com/products/abbyy-intelligent-document-processing/reviews), [Capterra](https://www.capterra.com/p/177446/ABBYY/reviews/)).
- **Kofax/Tungsten Capture.** A batch class holds document classes, which hold form types, and it must exist before scanning ([docs](https://docshield.tungstenautomation.com/KC/en_US/11.1.0-40hy9nfk91/help/main/KC_administration/batchclasses/c_batchclasses.html)). The batch's state is the queue it sits in, and queues are modules ([codecentric](https://www.codecentric.de/en/knowledge-hub/blog/kofax-capture-customisation-beyond-standard-features)). Only documents that fail validation go to operators ([codecentric](https://www.codecentric.de/en/knowledge-hub/blog/kofax-capture-customisation-beyond-standard-features)). Reviewers mention a steep learning curve, a dated UI, and licensing that is "significant… for smaller organizations" ([G2](https://g2.com/products/tungsten-capture/reviews), [TrustRadius](https://www.trustradius.com/products/tungsten-capture/reviews/all)).
- **PaperStream Capture** separates documents by blank page, page count, zonal OCR, patch code, 1D/2D barcode or hot key. Pro adds automatic profile selection and up to 20 metadata fields ([Fujitsu](https://www.fujitsu.com/uk/products/computing/peripheral/scanners/business/paperstream/ps-capture/), [Automate Routines](https://paperstream-dev.azurewebsites.net/en-gb/features/automate-routines)). This is the feature set office staff already see on their scanner's bundled software.
- **Laserfiche Quick Fields** zone OCR is described as fast for invoices ([TrustRadius 2014](https://www.trustradius.com/reviews/laserfiche-2014-08-01-07-19-08)) but also as "primitive and out of date" with a high OCR error rate ([TrustRadius 2018](https://www.trustradius.com/reviews/laserfiche-2018-07-03-09-55-04)). The same review says non-programmers build workflows with heavily duplicated activities. Laserfiche's own docs warn that a zone defined in percentages moves when the page size changes ([Laserfiche](https://doc.laserfiche.com/laserfiche.documentation/11/administration/en-us/Subsystems/QuickFieldsAdmin/Content/Processes/Zone-OCR.htm)).
- **DocuWare.** Indexing "works pretty much flawlessly" for some users ([G2](https://www.g2.com/products/docuware/reviews)). The Folder Import tool can fail "silently" and block a big upload with no notice ([Capterra](https://www.capterra.com/p/77706/DocuWare/reviews/)). Users also cite cloud storage costs, little control over cloud data and limited offline access ([G2](https://www.g2.com/products/docuware/reviews), [Capterra](https://www.capterra.com/p/77706/DocuWare/reviews/)). On-prem Workflow Manager is an add-on, and the designer moved from a desktop app to the web ([KC](https://knowledgecenter.docuware.com/docs/news-714-web-based-workflow-designer-for-on-premises)).

### 3.6 Fill and merge tools
- **Word mail merge.** Dates come through as serial numbers and leading zeros vanish, because the default OLE DB link pulls values but not formats. The fixes are field switches, switching to DDE, or text columns in Excel ([Ablebits](https://www.ablebits.com/office-addins-blog/mail-merge-formatting-issues-word/), [MS Q&A](https://learn.microsoft.com/en-us/answers/questions/4799028/mail-merge-date-format-problem), [Middlesex KB](https://www.middlesex.mass.edu/KB/Articles/Public/233)). Turkish chamber data is full of exactly these values (tax numbers, registry numbers, dates).
- **LibreOffice mail merge** has a long bug history: crashes on any merge (bug 144000), empty fields from registered data sources (bug 139906, fixed in 7.2 with a warning), and crashes on Exchange Database (bug 147637) ([144000](https://www.libreoffice.org/bugzilla/show_bug.cgi?id=144000), [139906](https://www.libreoffice.org/bugzilla/show_bug.cgi?id=139906), [147637](https://www.libreoffice.org/bugzilla/show_bug.cgi?id=147637)).
- **Acrobat** has no built-in Excel → many-PDF-forms merge. Users rely on PDFMaker in Word, paid scripts, or their own Python ([Adobe community](https://community.adobe.com/t5/acrobat-discussions/can-you-mail-merge-data-into-a-fillable-pdf-from-excel/td-p/10055335)). **Foxit** imports one record from FDF, XFDF, TXT, XML or CSV, and can combine many forms into one CSV ([Foxit](https://resource-cms.foxit.com/foxit-pdf-editor-for-windows/importexport-form-data), [Foxit](https://resource-cms.foxit.com/index.php/foxit-pdf-editor-for-windows/combine-forms-to-a-sheet)). **PDF-XChange** "Populate Forms" makes one PDF per CSV row and can "Guess" the mapping when names match. It does not work with XFA forms ([PDF-XChange help](https://help.pdf-xchange.com/pdfxp9/populate-forms_ed.html), [forum](https://forum.pdf-xchange.com/viewtopic.php?p=194972)). Every one of these tools ties the mapping to identical names: "field names in the data and the form must be the same."

### 3.7 Turkish products
- **TS 13298** is the TSE standard for EBYS. It was first published in 2007, and the 2015 revision added inter-agency sharing and KEP ([TSE](https://www.tse.org.tr/?p=10605), [AB13 paper](https://www.ab.org.tr/ab13/kitap/yilmaz_ts13298_AB13.pdf)). Public tenders reference it ([DergiPark](https://dergipark.org.tr/en/download/article-file/567942)).
- **Türksat Belgenet** is a "national" EBYS with KEP, PTT and archive integrations and a cloud option. Türksat reported 106 institutions using it in 2025 ([Türksat](https://turksat.com.tr/en/ict/products/belgenet-turkeys-electronic-document-management-system), [Türksat news](https://turksat.com.tr/en/news/belgenet-difference-digitalization)). Users must install an e-imza client before they can sign ([MEB guide](https://mus.meb.gov.tr/meb_iys_dosyalar/2024_04/24125843_turksateimzakurulumuveebysyegirisdokuman1.pdf)).
- **Bimser eBA** is listed as cloud or on-prem with approval and BPM features ([Software Advice](https://www.softwareadvice.co.uk/software/65081/eba)). Bimser's Synergy platform uses BPMN 2.0 ([SAP](https://www.sap.com/norway/products/erp/partners/bimser-cozum-yazilim-ticaret-anonim-bimser-synergy-low-code-platform.html)). Architecture details are unverified.
- **TOBB** supplies central software to chambers: member registry, accounting, ATR and exchange registration ([TOBB slide](https://mobil.tobb.org.tr/HaberResimleri/5614-8.pdf)). There are 252 chambers and 113 exchanges ([Ticaret Bakanlığı](https://ticaret.gov.tr/ic-ticaret/sikca-sorulan-sorular/odalar-borsalar-ve-tobb)). I found **no Turkish product aimed at scanning and splitting paper, reading form boxes, or filling forms inside a chamber office** (unverified absence).

## 4. Gaps no product fills for a small Turkish chamber office

1. **Windows-native, installer-only, offline capture.** The open-source DMS tools need Docker and Linux ([Paperless](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/setup.md)). The commercial suites need a server and IT staff ([ABBYY](https://docs.abbyy.com/flexi-capture/admin-guide/architecture-ag), [G2](https://www.g2.com/products/abbyy-intelligent-document-processing/reviews)). Desktop tools stop at a single step.
2. **Zonal OCR that a clerk can set up.** Only the expensive suites (ABBYY, Kofax, Laserfiche, PaperStream Pro) offer it. None of the open-source DMS tools has it.
3. **One job covering split, read, review and export.** No open-source tool keeps a scanned pile together as a job with its review state and Excel index.
4. **Two-way Excel work.** Tools either fill forms from data (mail merge) or extract data to a sheet (Foxit form-to-sheet). Checking a scanned set against an existing sheet is missing everywhere I looked.
5. **Robust mail merge with Turkish formats.** Dates, leading-zero IDs, Turkish characters and many rows into PDF forms are all weak spots in Word, LibreOffice and Acrobat.
6. **Light shared job states on a LAN without a server.** The DMS tools have permissions or full workflows, nothing in between. Teedy's APPROVE/VALIDATE is the closest, but it needs a web server.
7. **Turkish UI and Turkish document conventions** (vergi no, sicil no, TC kimlik checksums) in capture tools. Stirling-PDF has 40+ UI languages, but the capture suites' Turkish coverage is unverified.
8. **A licence model that small public-adjacent bodies can trust.** The Stirling-PDF and OpenKM licence changes show that the community watches this closely.

## 5. Lessons for Evrakçı

1. **Copy Paperless's two separator types** and name them in the UI. A separator sheet is removed, like PATCHT. A "document-start" code keeps its page, like ASN. Also accept the standard Patch-T sheet so offices can reuse the separator sheets their scanner software already prints ([Paperless config](https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/docs/configuration.md), [NAPS2](https://www.naps2.com/doc/batch-scan), [PaperStream](https://www.fujitsu.com/uk/products/computing/peripheral/scanners/business/paperstream/ps-capture/)). Warn when the scan is below 300 DPI ([NAPS2](https://www.naps2.com/doc/batch-scan)).
2. **Copy the Kofax/ABBYY hierarchy, but keep it small.** Job type ≈ batch class, document template ≈ document definition, field box ≈ zone. Put job state in a few named stages (Taranmış → Bölünmüş → Okunmuş → Kontrol edildi → Dışa aktarıldı). Users ask for this structure, but the suites hide it behind admin consoles ([Kofax](https://docshield.tungstenautomation.com/KC/en_US/11.1.0-40hy9nfk91/help/main/KC_administration/batchclasses/c_batchclasses.html), [ABBYY](https://docs.abbyy.com/flexi-capture/admin-guide/architecture-ag)).
3. **Review only what needs review.** Kofax sends only documents that failed validation to operators ([codecentric](https://www.codecentric.de/en/knowledge-hub/blog/kofax-capture-customisation-beyond-standard-features)), and ScanTailor highlights outlier pages in red ([ScanTailor](https://gitea.com/zvezdochiot/scantailor-advanced)). Evrakçı's Kontrol view should open on low-confidence and failed-checksum fields first.
4. **Anchor zones to page features, not absolute percentages.** Zones drift when page size or scan offset changes ([Laserfiche](https://doc.laserfiche.com/laserfiche.documentation/11/administration/en-us/Subsystems/QuickFieldsAdmin/Content/Processes/Zone-OCR.htm), [ABBYY fixed vs semi-structured](https://docs.abbyy.com/flexi-capture/fls/overview/about)). Use QR or registration marks to align pages before reading zones.
5. **Never fail silently.** DocuWare's silent import failure is a top complaint ([Capterra](https://www.capterra.com/p/77706/DocuWare/reviews/)). Every job should end with a visible Turkish summary: so many pages, so many documents, so many fields that need checking.
6. **Treat merge data as text with explicit formats.** Word drops leading zeros and turns dates into numbers ([Ablebits](https://www.ablebits.com/office-addins-blog/mail-merge-formatting-issues-word/)). Evrakçı should read Excel cells with their display format, keep IDs as strings, and show a preview of a few filled records before generating hundreds.
7. **Make the mapping explicit and editable.** PDF-XChange and Acrobat require identical field and column names ([PDF-XChange](https://forum.pdf-xchange.com/viewtopic.php?p=194972), [Adobe](https://community.adobe.com/t5/acrobat-discussions/can-you-mail-merge-data-into-a-fillable-pdf-from-excel/td-p/10055335)). Offer a "Guess" button that auto-matches names ([PDF-XChange Populate Forms](https://help.pdf-xchange.com/pdfxp9/populate-forms_ed.html)), then let staff drag to fix the rest, and save the mapping with the template.
8. **Ship the OCR and PDF dependencies inside the installer.** OCRmyPDF's Windows problems come from separately installed Tesseract and Ghostscript, PATH lookups and bitness mismatches ([OCRmyPDF docs](https://ocrmypdf.readthedocs.io/en/v14.1.0/installation.html)). NAPS2 shows the Windows-native route: bundled Tesseract, WIA and TWAIN with a 32-bit worker ([NAPS2 wiki](https://github.com/cyanfish/naps2/wiki/3.-Project-Structure)). Never ask staff to install Docker or Python.
9. **Keep job sharing simple and file-based.** A full Mayan-style state machine is overkill and attaches to single documents ([Mayan forum](https://forum.mayan-edms.com/t/one-workflow-for-more-than-one-document/260)). Teedy's two step kinds, VALIDATE (done) and APPROVE (yes/no) ([Teedy](https://raw.githubusercontent.com/sismics/docs/master/docs-core/src/main/java/com/sismics/docs/core/constant/RouteStepType.java)), plus an audit log and comments, cover "finished / not finished / who has it". Put them in a job folder on a shared drive with a lock file, so no server is needed. (This is a design inference, not tested prior art.)
10. **Be clear about the licence from day one.** AGPL with a commercial dual licence is workable, and Docspell uses AGPL ([Docspell](https://raw.githubusercontent.com/eikek/docspell/master/README.md)). The Stirling-PDF and OpenKM backlash came from moving features behind a paywall and closing source after the fact ([isitreallyfoss](https://isitreallyfoss.com/projects/stirling-pdf/), [OpenKM](https://www.openkm.com/blog/openkm-community-edition-v70-a-new-stage-for-open-source-document-management.html)). Decide now what stays open, and never gate features through configuration flags inside the AGPL build.
11. **(Bonus) Don't compete with EBYS.** Belgenet and similar systems own official correspondence, e-imza and KEP ([Türksat](https://turksat.com.tr/en/ict/products/belgenet-turkeys-electronic-document-management-system)). Evrakçı should export clean, named PDFs and indexes that staff can upload into EBYS. It should not try to be a TS 13298 system itself.
