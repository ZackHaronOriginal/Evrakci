# Dışa Aktar audit: motion

Phase 4, Görev A, screen Dışa Aktar. Every animation on the screen: duration, curve, trigger, reduced motion, whether it blocks input. Measured by sampling the toast's opacity every 10 ms offscreen and by counting `QAbstractAnimation` children of the window in each state (`p10_motion.py`, output in `/tmp/claude-0/p4/disa-aktar/motion.log`), and by reading `grep -n "Animation\|motion\." ui/disa_aktar*.py` (no hit): this screen's code starts no animation of its own. Reduced motion was forced with `motion.set_reduced_motion_override(True)`.

After every run no animation object of this screen is left alive (1 shared object before, during and after). Nothing on this screen moves on a frequent action, so no motion finding comes from the rule "any motion on a frequent action is a finding". For a user with weak eyesight the practical point is the reverse: while a run goes on, the only change is a number and a bar that step once per file; the spinner does not turn. That is F-disa-aktar-27 (S4).
