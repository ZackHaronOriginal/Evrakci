# Dışa Aktar audit: state matrix

Phase 4, Görev A, screen Dışa Aktar. Rows are elements or groups from `disa-aktar-inventory.md` (E-ids). Columns are the states from the phase plan. Every cell is a screenshot reference (`S:<name>`), a path row (`P-nnn` in `disa-aktar-paths.md`), a measured row (`M:`), a fact from the long-content runs, or `n/a: reason`. A cell that could not be filled says `GAP: reason` instead of a guess; the gaps are counted at the end. A cell that holds a mix of references and words is still counted as a reference.

How the cells were made (all offscreen, synthetic data, window 1366x768, light 100 % unless the name says otherwise): `tools/screenshots.py` windows built fresh in each theme and text size (no runtime theme switching; the app configured as `screenshots.py` does: custom frame, fonts, style sheet), driven with QTest and direct calls on `DisaAktarScreen`; a gate inside a wrapper of `export_job` holds a real run so that the writing state can be shot. Screenshot files are `/tmp/claude-0/p4/disa-aktar/states/<name>-<tag>.png` (253 files); the tag is the theme and text size (`light100`, `dark150`, `hc100`; the states exist for all three, the long-content, failure and retention runs mostly as `light100`). Names: B1-default; A1-empty (no job); E-blocked-* (full folder, a file as target, unknown variable); E-no-folder-error; S-rows-selected; S-filter-on; R-running, R-stopping, R-stopped, R-done, R-failed; H-* focus, hover, pressed and menus of the first pass; H2-* hover, pressed and focus of the second pass (command bar, buttons, checkbox, links, outcome buttons); L1..L6 long content (L1 names, L2 target path, L3 400 documents, L4 big counts, L5 long reasons, L6 path fit); B008-* the deleted job; U-* the undo case. The 72-screenshot matrix (`tools/screenshots.py matrix --allow`) is in `/tmp/claude-0/p4/disa-aktar/matrix/` (tab slug `disa-aktar`).
