# Yükle audit: state matrix

Phase 4, Görev A, screen Yükle. Rows are elements or groups from `yukle-inventory.md` (E-ids). Columns are the states from the phase plan.
Every cell is one of: a screenshot reference, a path row (`P-nnn` in `yukle-paths.md`), a measured row (`M:`), or `n/a: reason`. A cell that could
not be filled says `GAP: reason` instead of a guess; the gaps are counted at the end.

How the cells were made (all offscreen, synthetic data, window 1366x768, text 100 percent unless named):
- Screenshots: `/tmp/claude-0/p4/yukle/states/<theme>-<name>.png`, theme `light`, `dark`, `hc` (414 files; every `S:<name>` below exists in all three themes).
  Written by `states.py`, `long.py`, `extra.py`, `extra2.py` (session scratchpad): a fresh window per theme, the element put into the state with
  QTest (mouse move, press, Tab focus, selection, delete, context menu event, a held read through a patched `prepare_batch`, a failed read with a broken file,
  `show_drop` for the overlay) and `window.grab()`. Long-content cases (long names, 120 batches, 40 batches without QR, 29 jobs, 60 dropped files,
  40 files being read, 5-digit page counts) are named `L1` to `L12`, `Z1` to `Z4`, each at 100 and 150 percent and at 1366x768 and 1920x1080.
- The 72 matrix files are in `/tmp/claude-0/p4/yukle/matrix/` (`tools/screenshots.py matrix --allow`: 72 images, **0 KIRPILMA**: the demo data hid every overflow below).
- Measured: `/tmp/claude-0/p4/yukle/measure.tsv` from `python tools/ui_measure.py --tab yukle` (3 themes x 2 sizes x 2 text sizes, default state only): 4824 rows,
  4753 pass, 14 fail, 57 skip. The 14 fails are DEC-CON-01 on the Durum column (8 rows, F-yukle-22) and DEC-FOC-01 on `titleBand/titleTabs` (6 rows, a
  single-tab-run artefact, ledger B-041). The same tool run on my own state windows (empty page, no match, reading, error, drop) is in
  `/tmp/claude-0/p4/yukle/states-measure-fails.tsv` (dark and hc; light was read from the console): F-yukle-26, F-yukle-32, F-yukle-38.
  The tool measures the default state only; hover, pressed and focus colours are not measured (GAP in those cells, the screenshots are the evidence).
- Screenshot numbers: 01 default, 02 three batches with the Toplam row, 03 row hover, 04 row pressed, 05 row focused, 06 selected with the table unfocused,
  07 Toplam row hover, 08 header edge hover, 09 grip hover, 10 to 13 inspector buttons (focus, hover, pressed, menu open), 14 to 16 command bar,
  17 row context menu, 18 toast after Del, 19 inspector hidden (F9), 20 reading (waiting), 21 reading (progress), 22 queued-drop toast, 23 cancelling,
  24 after cancel, 25 failed read (error bar), 26 empty page with jobs, 27 to 33 empty page states and "Tüm işler", 34 and 35 drop overlay,
  L1 to L12 and Z1 to Z4 as above.
- In hc, a disabled control is drawn in `GrayText` (bright green in the Windows "Black" high-contrast theme, which is also what the offscreen palette gives):
  by design (DESIGN.md: "GrayText for disabled only"), not a finding. Selection in hc is the cyan fill with black text; focus is the ring.
