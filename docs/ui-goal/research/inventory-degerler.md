# Inventory: Değerler tab

Research file, written from the code as it stands. Nothing here is a decision. "Observation" items at the end are things that look missing, inconsistent or awkward; each carries its evidence so the owner can judge.

Sources read: `src/evrakci/ui/degerler.py`, `degerler_model.py`, `degerler_table.py`, `degerler_side.py`, `degerler_parts.py`, `actions.py`, `main_window.py` (wiring), `controller.py`, `loupe.py` (shared), and the core: `pipeline/review.py`, `pipeline/cuts.py`, `pipeline/job.py`, `pipeline/templates/{model,read,values}.py`, `pipeline/ocr/{engine,tesseract,metrics}.py`, `pipeline/render.py`, `pipeline/naming.py`. Tests read: `tests/ui/test_degerler.py`, `test_degerler_model.py`, `test_review_fixes.py`, `test_phase4.py`, `test_shell.py`, `test_actions.py`, `test_integration.py`, `tests/test_review.py`, `test_templates_review2.py`, `test_template_read.py`, `test_cli_values.py`.

Conventions. File names are under `src/evrakci/` (`ui/degerler.py` is written `degerler.py` when the folder is clear). Line numbers are from the current files. "Tests" names a test file and, where useful, the test function; "none" means no test found by reading and grepping `tests/`. Test paths are relative to `tests/`. The test suite was not run, except one scratch probe described under Observations (O-05). Category tags are from the list in the task.

One fact to hold in mind: this tab has no per-variable "type". The core knows no types (`pipeline/templates/model.py` header: "The code knows no fields, types or document kinds"). The only per-column treatment is a display guess from the text itself (V-18).

## Observations

Each item is an observation, not a decision. "Evidence" says where it comes from; "probe" means a scratch test run outside the repository.

- **O-01 No cell-level state in the table, only row-level.** A document with one Kontrol value and three Emin values shows the text of all four in the same look; only the marked characters (when any) and the row's Güven word ("Kontrol %55") tell the user something is wrong, and not which cell. A flagged value with identical readings and no letter next to a digit gets no mark at all. Evidence: `degerler_table.py:ValuesDelegate._value` (580-593) paints only `cell.uncertain`; `Row.level` (257) is the only level drawn per row.
- **O-02 Two different counting units.** The view switch counts values ("Kontrol gerekenler 1") while the table lists documents; the status bar counts across all templates while the switch counts only the picked template. Evidence: `degerler.py:_fill` (496-499) uses `template_rows`; `_update_status` (1357) uses `self.rows`.
- **O-03 Next-kontrol availability disagrees with the picked template.** The N commands are enabled by the count over all templates (`_sync_actions`, 1309), but the search runs only in the picked template's rows, so N can say "Kontrol bekleyen değer yok." while the status bar says "N değer kontrol bekliyor". Same for the sample, which draws from all templates while the picker is hidden (`set_sample`, 833).
- **O-04 Unread or failed documents are easy to miss.** Kontrol gerekenler and İncelenmemiş exclude documents with no values (`degerler_model.py:in_view`, 340-345), the status bar warns only when nothing at all is read (`_update_status`, 1340), `Counts.unread_documents` is computed and never used (grep: only its definition), and `Row.error` is shown only in the inspector line when that row is selected (`_describe`, 1044). A document added to the job after reading appears only in Tümü, with blank cells. Ledger B-014 (open) records the missing unread count; strict-xfail repro in `ui/test_ledger_c.py`.
- **O-05 The saved template choice is not restored.** The picker pref ("degerler.sablon") is read in `attach` (318) and then discarded by `_fill`, which sets `_template_id = None` the first time it sees a job id (`degerler.py:480-484`). Probe: two templates, pref set to the one with no Kontrol values, window created, job opened after the window; the screen picked the other template (the one with most Kontrol). Ledger B-010 (open) with a strict-xfail repro. Existing test `test_degerler_view_template_and_snap_are_remembered` only checks the view, not the template.
- **O-06 A failed read lost finished work (fixed at HEAD).** This was true when the file was first written. Since cefd148 `_read_failed` (1475) calls `_store(self._results)` first, like the cancel path (`_read_cancelled`, 1479), and `ui/test_ledger_c.py::test_b011_values_read_before_an_unexpected_error_are_kept` is no longer marked xfail (ledger B-011; the suite was not run for this file). The error band still shows only the message. Per-document errors (engine, OS, PDF) are caught inside the loop and do not hit this path.
- **O-07 Inconsistent naming of the variant action.** Menu, palette and context menu say "Yeni varyant çiz"; the inspector button and its tooltip say "Yeni kutu çiz (V)"; Şablonlar says "bölüm" and the Değerler reason line says "Varyant N"; the first box is "Bölüm 1" here but "Kutu 1" in Şablonlar' inspector. Evidence: `actions.py:308`, `degerler_side.py:565, 580`, `degerler_model.py:section_name` (72).
- **O-08 Variant drawing lands on page 1.** The hand-off sets the example document but never the page; a variable whose box is on page 2 or on the last page opens on page 1 of that document. Evidence: `main_window.py:_draw_variant` (1312-1328) has no `set_page_number`; `sablon.py:set_example` resets `page_number = 1` (656). Ledger B-013 (open); the repro test is a strict xfail.
- **O-09 "Değerlerde aç" does not select the document.** The Kontrol signal carries the document number and the connection throws it away (`main_window.py:1153`). Ledger B-012 (open); strict-xfail repro in `ui/test_ledger_c.py`.
- **O-10 No "elle" (typed by hand) filter or tag, and no way to see what was machine-read after accepting.** A typed value and a confirmed one are the same state (V-34). The user cannot list "everything I changed", and the only way back is Ctrl+Z (the core's `revert_value` is CLI-only, V-65). Export's `index.xlsx` content for edited values was not part of this reading.
- **O-11 Empty text is a valid value.** Clearing a cell and pressing Enter stores an empty, İncelendi, "Emin" value without any message; for a required variable the export will then fail the file name. Evidence: `degerler.py:_apply_edit` (1191-1210) has no empty check; `review.py:set_value` accepts "".
- **O-12 `required` is invisible here.** The table and the inspector never show whether a variable is required, though a missing required value decides the file name at export (V-96). Evidence: `Cell.required` is set but never read in the UI.
- **O-13 Mixed templates in one document are not shown.** The row uses the template of the document's first page; the core flags `mixed_templates` and Dışa Aktar writes "karışık şablon", but Değerler shows nothing. Evidence: `degerler.py:build_rows_fast` (103), `pipeline/cuts.py:148`, `pipeline/export.py:43-46`.
- **O-14 The sample is not saved.** `_samples` is an in-memory dict (`degerler.py:149`); closing the app or re-drawing loses the 20 picks and their progress, though the corrections and İncelendi marks stay.
- **O-15 Whole-page view does not show where the value is.** The Loupe opens plain pages; the box outline exists only in the small crop (`toggle_whole_page`, 1083-1108).
- **O-16 The inspector shows one reading and one suggestion.** All section readings are stored (`VariableValue.readings`), including each one's confidence, but the card shows only the first-variant text and the best-reading suggestion; the user cannot see "variant 1 said X at 41 %, variant 2 said Y at 55 %". Evidence: `ValueCard` (455-505).
- **O-17 Display type guesses are content-based.** `column_kind` decides number, date, code or text from the values read (including misread ones), so a column can change look and sort mode after a re-read; the product line is "the user decides what documents contain". Evidence: `degerler_model.py:81-93`, `degerler_table.py:main_columns` (77).
- **O-18 Duplicated threshold constant.** Emin at 0.90 is defined in `degerler_model.py:31` and again in `sablon_read.py:22`; the two tabs agree today only because both use the same number (Şablonlar uses `max(0.90, threshold)`, Değerler never sees an unflagged value below the threshold).
- **O-19 Untested areas, found by grep:** Ctrl+G, Ctrl+F, Esc in the search field, the hand-off to Şablonlar, multi-template picking, flagged read failure paths, the 150 % header wrap, the "unread" status text, and the tooltip texts.
- **O-20 Docs drift.** `docs/ui-goal/shortcuts.md` still says "Status: Phase 2 groundwork ... not yet wired into main_window.py"; the registry is wired (`main_window.py:_wire_actions`). The Vazgeç tooltip is "Değişikliği bırak" (`actions.py:311`) while the action only closes the page view or reduces a multi-row selection (`degerler.py:dismiss`); the editor keeps its own Esc.
- **O-21 Command line has more.** `evrakci is degerler --kontrol`, `is deger … --oneri` and `--geri-al` give the same fix and revert; the window has no equivalent of `--geri-al` for a single value other than Ctrl+Z (V-65).
- **O-22 Reading cost per document.** `render_page` opens the PDF again for each page (`pipeline/render.py:15-28`), and the Değerler worker calls it per page request, while the CLI `sablon test` uses `PageRenderer` to open the file once (`render.py:33`, `cli/templates.py:test_template`). Impact on large batches was not measured.
- **O-23 Değerler toasts use an older Geri al guard than the other tabs.** `degerler.py:_toast` checks only the history position (`index() == index`) and passes no `available` to the toaster, so the button is not hidden when the history moves. After Ctrl+Z and a different edit that lands on the same position within 10 s, the old toast's button would undo the new edit (the failure class of ledger B-023, which cefd148 fixed for Kontrol and Şablonlar through `feedback.undo_last`). By code reading; not probed. Evidence: `degerler.py:_toast` (1165-1173), `feedback.py:undo_last` (157).
- **O-24 Template threshold is invisible from the table too.** A value reaches Kontrol when it falls under the template's `min_confidence` (default 0.70), a number that no window screen shows or edits (S-10, V-36); a user who sees "Kontrol 65 %" cannot tell what the bar was. Evidence: `templates/model.py:set_min_confidence` (186), `degerler_model.py:EMIN_AT` (31).
