# Inventory: Dışa Aktar tab

Scope: everything a user can see or do on Dışa Aktar (named PDFs plus `index.xlsx`), the core it calls (`pipeline/export.py`, `exporting.py`, `naming.py`, `writer.py`, `index.py`, `settings.py`, `store.delete_older_than`), the retention setting in Ayarlar, and the CLI behaviour where it is the same code (the "[kontrol]" marks).

Method: read from code and tests; nothing was run. "Tested?" names the test that asserts the behaviour; "none" means no test found by reading `tests/`. Turkish UI strings are quoted as in the code. Line numbers are from the checkout at commit 589522f.

Short names: `DA` = `src/evrakci/ui/disa_aktar.py`, `model` = `ui/disa_aktar_model.py`, `side` = `ui/disa_aktar_side.py`, `table` = `ui/disa_aktar_table.py`, `parts` = `ui/disa_aktar_parts.py`, `banners` = `ui/disa_aktar_banners.py`, `T` = `tests/ui/test_disa_aktar.py`, `G` = `tests/ui/test_export_guide.py`, `RF` = `tests/ui/test_review_fixes.py`, `P4` = `tests/ui/test_phase4.py`.

Constants found: file name limit 120 characters (`naming.MAX_LENGTH`); whole path limit 250 UTF-16 units less the folder path and the longest suffix " (999).pdf.gecici" (`naming.PATH_LIMIT`, `fit_names`); side panel 368 px (440 at large text); file list measures names of at most the first 500 rows to size the name column (`_name_need`); no cap on the number of documents was found.

## Observations

These are observations, not decisions.

1. **Counts disagree about "PDF/A değil".** The list shows it as Bilgi (model:file_rows splits `PDF/A değil` out of the checks), but `ExportResult.needing_check` counts every item with any check, and `index.xlsx` puts "evet" in "Kontrol gerekli" for it (exporting.py:ExportResult, index.py). So the outcome card can say "N belge kontrol gerektiriyor" while the list shows no Kontrol row for those, and `may_delete_after_export` keeps the job for it. No test covers a PDF/A failure through the window. Ledger B-003 (S3, open): strict xfail test `test_ledger_b.py::test_b003_...`.
2. **"Sayfalar" is a range, not a count.** `pages_text` prints first and last source position ("5–9"). A document with a deleted page or from a filter shows a range larger than its page count; `index.xlsx` has the true "Sayfa sayısı" and the full list. The printed index (D-53) uses the range, though its docstring says it shows "what index.xlsx lists". Page numbers also move if batches are reordered after export.
3. **A pattern edit lives only in memory and replaces every template's pattern.** `_overrides` is a dict on the screen (disa_aktar.py:135); nothing saves it to the template or the job, and `_effective` rewrites every used template's pattern (393-398). After a restart the field shows the template's pattern again, and the CLI export (which reads the template) names files differently from a window export that used an override. The test for the CLI match uses no override (G::test_window_export_matches_the_cli). Ledger B-004 (S3, open): manual step only, no test.
4. **The pre-filled folder is usually a full one.** With no default folder set, the last export folder is offered (D-16), and that folder now holds the previous export, so the next export normally opens on an Engel and needs "Yeni alt klasör oluştur" (the code comment in `_prefill_folder` says this is intended). A first-time user sees the same after one export.
5. **A job with zero documents looks like "no job".** `_compute_state` returns `empty` when the plan has no items, and the empty pane tells the user to open a job from Yükle (parts:EmptyPane). A job made only of separator pages, or with every page deleted, therefore shows the wrong sentence. Test covers only the no-controller case.
6. **After "delete after export" the job stays open in the window.** `DisaAktarScreen.job_deleted` is handled only by `MainWindow._job_deleted`, which removes `son-is.txt` and refreshes the list (main_window.py:1228). No handler closes the open job (grep). Reading the code, the next edit would call `store.save` and recreate `job.json`, but the batch PDFs are gone; not run. The card does say "İş silindi (saklama ayarı)." No window-level test. Ledger B-008 (S2, open): strict xfail test `test_ledger_b.py::test_b008_...`.
7. **Retention wording.** The Ayarlar note says "Dışa aktarılan iş bu bilgisayarda ne kadar saklansın.", but the day limit also deletes jobs never exported (README; `delete_older_than` does not look at export state). The window offers 30 and 90 days only; the CLI accepts any number. When "Tam dışa aktarınca sil" is on and the job is kept because documents need a check, the card gives no reason (the CLI does: "İş saklandı: N belge kontrol gerektiriyor"). No warning before the day limit deletes a job at start-up was found in the code. Ledger B-005 (S1, open, owner question Q-01): strict xfail test `test_ledger_b.py::test_b005_...`.
8. **Stopping during the text-layer stage.** The stop message counts files in the folder and says `index.xlsx` was not written, but not that some of them lack the text layer. The folder is then not empty, so the next export needs another folder (the stop message itself says so). In the layer stage a stop raises before the index fallback used for engine failures, so no index is written (exporting.py layer loop).
9. **Label says "değiştir", text says "silinir".** The checkbox reads "Geçersiz karakterleri değiştir", but the tooltip and the core (`_FORBIDDEN.sub("", …)`) delete the characters. A user may expect a replacement character.
10. **No document number in the list or the printed index.** The list is sorted with Kontrol first, `index.xlsx` is in document order, and the only link between a row and "belge_NNN" is the name (and only for numbered names). `index.xlsx` has no number column, no job name and no export time.
11. **"Kaynak sayfalar" is every page number.** For a 40-page document the cell lists 40 numbers (index.py joins each position); no ranges, and no hyperlink from a row to its file.
12. **Unexpected errors show raw text.** `Task.run` reports any non-core exception as `str(error)` or the class name (workers.py:49), and the failed card shows that text as it is, possibly English. Core errors are Turkish.
13. **The default (text layer on) is not exercised through the window.** Every UI export test unchecks the layer (grep `layer.setChecked(False)`); the stub layer and engine are tested in the core. Real OCR time per document is not estimated before the user starts, and the checkbox is not remembered. Ledger B-009 (S3, open): strict xfail test `test_ledger_b.py::test_b009_...`.
14. **Folder check runs on every keystroke.** `folder_state` lists the directory (`iterdir`) each time the text changes, on the window thread; on a slow network share it could lag. Unclear, not measured.
15. **Not verified.** Opening files and Explorer reveal (Windows only), the printer path on real hardware, and any export of more than a few documents were not run. The ETA wording was read, not observed.
16. **New 2026-11-19: a blocked export is announced as "info".** When an Engel stops `export()`, the toast "Dışa aktarılamıyor: <first engel>" is shown with kind "info", and only the first Engel title is named even when there are several (`blocked[0].title`). The Ön kontrol card still lists all of them. Evidence: `ui/disa_aktar.py:export (L890-L905)`. From code reading, not run.
17. **New 2026-11-19: no step between "Kontrol" and writing.** Kontrol rows never stop the export (D-03) and the card offers only a link to jump to the first check; there is no per-file "seen" mark, and Kontrol's İncelendi approvals (K-58) are not read by this tab at all: grep of `disa_aktar*.py` finds no use of `ReviewStore` or `incelendi`. A document the user approved on Kontrol is counted as "kontrol bekliyor" here exactly as before. Evidence: `ui/disa_aktar_model.py:findings (L210)`, `ui/kontrol_review.py`. From code reading.
18. **New 2026-11-19: ledger overlap.** Observations 1, 3, 6, 7 and 13 map to B-003, B-004, B-008, B-005 and B-009. The retention label question is also in `docs/ui-goal/OWNER-QUEUE.md` as Q-01.
