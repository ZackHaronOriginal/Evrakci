# Inventory: Yükle tab

Scope: everything a user can see or do on Yükle (jobs and batches), plus the core it calls for import and analysis (`src/evrakci/ui/yukle*.py`, `pipeline/store.py`, `pipeline/analyze.py`, `pipeline/job.py`, `pipeline/cuts.py`). Retention and export live in `inventory-disa-aktar.md`; the separator sheet in `inventory-rehber.md`.

Method: read from code and tests; nothing was run. "Tested?" names the test that asserts the behaviour; "none" means no test found by reading `tests/` (grep on the strings and function names). Turkish UI strings are quoted as in the code. Line numbers are from the checkout at commit 589522f.

Short names used below: `yukle.py` = `src/evrakci/ui/yukle.py`, `parts` = `ui/yukle_parts.py`, `info` = `ui/yukle_info.py`, `table` = `ui/yukle_table.py`, `side` = `ui/yukle_side.py`, `YA` = `tests/ui/test_yukle_a.py`, `Y` = `tests/ui/test_yukle.py`, `MW` = `tests/ui/test_main_window.py`.

Fixed constants found in code: `PDF_LIMIT = 5000` files per drop or dialog (parts:33), `SHOWN_FILES = 5` rows in the drop overlay (parts:34), overlay counts files only up to 200 (`parts.DropOverlay.show_drop`, `collect_pdfs(paths, limit=200)`), `EmptyPage.RECENT = 3`, `EmptyPage.ALL = 8` (parts:375-376), progress card redraw at most every 0.1 s (`REPORT_EVERY`, yukle.py:66), analysis render 100 dpi grayscale (`analyze._RENDER_DPI`), empty page = ink ratio below 0.003 (`EMPTY_INK_RATIO`), 6 % edge margin ignored, ink = pixel value below 160.

## Observations

These are observations, not decisions.

1. **Ctrl+O during a read is a silent no-op.** `choose_batch` with a job open goes to `add_batches` and then `_begin`, which returns without a word when a task runs (yukle.py:430-434, 885-886). Only drops and "Klasör ekle…" go through the queue in `add_paths`. The user picks files in the dialog and nothing happens. No test (YA tests the queue only through `add_paths`). Ledger B-001 (S3, open): strict xfail test `test_ledger_b.py::test_b001_...`.
2. **Batch "Kontrol" and inspector "Hazır" can disagree.** A batch with zero QR pages is "Kontrol" even when the user has already split it with a filter or manual cuts (info.py:83 looks only at QR count and export checks). In the same state the inspector says Durum "Hazır" (YA::test_inspector_shows_the_preflight_counts_and_the_profile asserts both for the same job). Ledger B-002 (S3, open): strict xfail test `test_ledger_b.py::test_b002_...`. The guide itself says equal-length documents need no separator (docs/tarama-rehberi.md, "Bilmeniz gerekenler").
3. **Scan profile is thin.** It reads only the first page of the first batch (yukle.py:_scan_profile, batches[0]); later batches with another resolution or colour mode are invisible. It never compares with the guide's recommendation (300 dpi, gray): grep finds no use of 300 in yukle*.py. The first read happens on the window thread. The link goes to the top of Rehber, not the "Tarayıcı ayarları" section.
4. **Drop overlay under-counts.** It counts at most 200 files (`collect_pdfs(..., limit=200)`) while the real limit is 5000, so a 700-file folder is announced as "200 parti". It also walks the folder tree on the window thread when the hovered set changes; cost on a slow share is unclear (not measured).
5. **Order of loose files is whatever the OS or dialog returns.** Only folder contents are sorted naturally. For a multi-file drop or dialog result the order in `find_pdfs` is the given order; what Explorer or the dialog supplies is unclear. Batch order decides page numbers, so a wrong order is a silent wrong split. The user can reorder (Y-14, Y-15), but nothing warns.
6. **Removed and undone batches leave their PDF copy on disk.** `remove_batch` and the undo of an add only change `job.json`; `prepare_batch` even keeps the name free "for an undone earlier batch" (store.py:prepare_batch). No cleanup was found (grep `unlink` in yukle.py: only on a cancelled read). Each import also doubles disk use (copy of every scan); no free-space check was found.
7. **No duplicate check.** Adding the same file twice creates two batches; only duplicate paths within one drop are removed (find_pdfs `seen`). Original path is not stored, only the file name (`Batch.file_name`).
8. **Dosya Gezgini shows internal names.** "Dosya Gezgini'nde göster" highlights `bN.pdf` inside the app data folder (store.batch_file), not the original `tarama-1.pdf`. Table names are elided with no tooltip (BatchModel.data has no ToolTipRole), so a long name cannot be read in full.
9. **Nothing to look at inside a batch.** Double-click and Enter do nothing on a row (no handler found); selection is single, so batches cannot be moved or removed together. The analysis already computes blank pages, yet Yükle shows no count of them, and the only way to drop blanks is the CLI `is bos-sayfalar` (cli/jobs.py:579); `JobController.set_drop_empty` is called by no screen. The guide says blank backs can be dropped "iş ayarından" (docs/tarama-rehberi.md); no such control was found in the window (re-checked 2026-11-19: `set_drop_empty` still has no caller under `ui/`). Ledger B-006 (S3, open): strict xfail test `test_ledger_b.py::test_b006_...`.
10. **Job list limits.** The list shows at most 8 jobs and the rest only by search; the window offers no way to delete or rename a job from the list (only `store.delete` caller in `ui/` is the export retention, disa_aktar.py:1008). `refresh_jobs` loads every `job.json` fully on the window thread each time (store.list_jobs); cost with many large jobs is unclear (not measured).
11. **Silent aborts in the name step.** An empty or cancelled name dialog ends with no message (yukle.py:419-421). Job names need not be unique.
12. **One bad file aborts everything.** A broken file in a multi-file add (or a new job) discards all pages analysed so far and removes the copies; the bar names the file, but the user must re-add the good ones. A password-protected PDF gets the same generic failure, with no password route (test asserts only that `BatchError` is raised).
13. **Progress estimate includes the counting phase.** `_Reading.started` is set when the read is created, before the worker has counted pages, so pages-per-second is lower early on (yukle.py:_Reading, _begin). Cancel is checked per page via the progress callback, so the page-count phase and the final file copy cannot be interrupted (workers.py:Task._progress). Likely, not measured.
14. **Vocabulary.** The UI and guide use "parti" (batch) throughout, but PRODUCT.md's terminology list has no entry for it. The command bar says "Dosya ekle…" while the result says "N parti eklendi."
15. **Not verified.** Whether Esc cancels a drag as the overlay note says is up to the OS drag loop; no code handles it. The whole drag-and-drop route with a real mouse (rows and files) was not run.

Observation 6's "no cleanup found" was re-checked against HEAD: `unlink` in `yukle.py` is still only on the cancelled-read path.
